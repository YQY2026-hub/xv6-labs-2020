问题 1：结合教材图 3-4 解释 vmprint 的输出

vmprint 打印的是进程 1（init）刚执行完 exec() 时的三级页表（Sv39：根表 L2 → L1 → L0），
缩进深度就是该 PTE 所在的层级，每行依次是页表页内的索引、PTE 原始值和它指向的物理地址。

第一级只有索引 0 和索引 255 有效：
- 索引 0 覆盖用户地址空间 [0, 0x40000000)，其下 L0 里映射了 0、1、2 三个页；
- 索引 255 对应内核高地址区：511 → 510 是 trapframe 页（TRAPFRAME），511 是 trampoline 页。

用户那三页分别是：
- 第 0 页：init 程序的可执行代码（text 段），PTE 为 0x...1f，带 PTE_R|PTE_W|PTE_X|PTE_U，
  用户态可读、可写、可执行；
- 第 2 页：用户栈，exec() 分配的两页栈中的最后一页，sp 初始指向它的顶端；
- 第 1 页：栈下方的保护页（guard page），PTE 为 0x...0f，只有 PTE_V|PTE_R|PTE_W|PTE_X
  而**没有 PTE_U**。

因此运行在用户态时，进程**不能**读写第 1 页映射的内存：PTE_U 被 exec() 里的 uvmclear()
清掉了，用户态一旦访问该页就会触发 page fault。这正是栈溢出时能被及时发现的机制——栈向下
生长越界会先撞上这个 guard page，而不是悄悄覆盖别的数据。

问题 2：copyin_new() 中第三个判断 srcva + len < srcva 为什么必要

它是用来检测 64 位无符号整数加法回绕（溢出）的。前两个判断
    srcva >= p->sz             （起点越界）
    srcva + len >= p->sz       （终点越界）
都建立在 srcva + len 没有回绕的前提上。一旦加法回绕，结果会变成一个很小的数，反而落回
合法区间，于是前两个判断都会失效、返回不了 -1，只有第三个判断能发现异常。

举例：设 p->sz = 0x1000，取 srcva = 0x800，len = 0xFFFFFFFFFFFFFFFF（即 2^64 - 1）：
    srcva >= p->sz          → 0x800 >= 0x1000     假，不返回 -1
    srcva + len >= p->sz    → 0x7FF >= 0x1000     假（已回绕），不返回 -1
    srcva + len < srcva     → 0x7FF < 0x800       真，返回 -1
如果没有第三个判断，内核就会拿着一个回绕后的长度去做 memmove，造成越界读写。
